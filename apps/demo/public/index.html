    What just happened

      The x402 problem this fixes

      x402 exact today: pay first
      • Bad data, paid anyway. Any successful response settles the payment before the agent can look at it. Stale prices, empty results, made-up fields: the money is already gone.
      • "Success" is all the seller has to say. x402 checks that a payment is valid, not that the data is.
      • No recourse. There is no refund operation and no chargeback, and no human in the loop to dispute it.
      Example: the cheating seller's quote
      {"symbol":"XRP","price":-1,"asOf":"2019-01-01T00:00:00Z"}
      Agent loses 1 XRP + fee, permanently.
      x402 auth-capture on XRPL: verify, then pay
      • Same 402 flow. One scheme registered in @x402/express and @x402/fetch.
      • Money waits in a native escrow that can only pay the seller with the arbiter's secret.
      • Bad data means no release, and the escrow refunds itself at the deadline.
      Run the cheating seller to see it live
      Arbiter: FAIL (price -1 is not a positive number)
      Agent loses only the 12-drop network fee.
