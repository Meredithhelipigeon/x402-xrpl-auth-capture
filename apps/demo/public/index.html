    What just happened

      The x402 problem Misa fixes
      x402 exact today: pay first
      • Bad data, paid anyway. Any successful response settles the payment before the buyer agent can look at it.
      • "Success" is all the seller has to say. x402 checks that a payment is valid, not that the data is.
      • No recourse. No refund operation, no chargeback, no human in the loop.
      Example: the cheating seller's quote
      {"symbol":"XRP","price":-1,"asOf":"2019-01-01T00:00:00Z"}
      Buyer agent loses 1 XRP + fee, permanently.
      In one independent test, 4 of 85 paid x402 calls returned nothing useful: an empty list, a partial snapshot, error messages. Source: dev.to/alexar76
      With Misa: verify, then pay
      • Same 402 flow. One scheme registered in @x402/express and @x402/fetch.
      • Money waits in a native escrow that only pays the seller with Misa's key.
      • Bad data means no release, and the escrow refunds itself at the deadline.
      Run the cheating seller to see it live
      Misa: FAIL (price -1 is not a positive number)
      Buyer agent loses only the 12-drop network fee.
